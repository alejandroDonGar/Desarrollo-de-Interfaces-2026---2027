📘 Comunicación entre widgets: propiedades y callbacks

Requisitos de finalización
📘 UT 2. Comunicación entre widgets

1.4 Comunicación padre → hijo

Ya sabes que un componente recibe sus datos a través del constructor. Esto tiene una consecuencia importante: el widget que contiene a otro (el padre) es quien decide qué datos muestra el componente (el hijo).

En esta pantalla el padre es PantallaAvisos y los hijos son las tres tarjetas:

class PantallaAvisos extends StatelessWidget {
  const PantallaAvisos({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Mis avisos')),
      body: const Column(
        children: [
          TarjetaAviso(mensaje: 'Información general'),
          TarjetaAviso(
            mensaje: 'Cuidado con los cambios',
            icono: Icons.warning,
            color: Colors.orange,
          ),
          TarjetaAviso(
            mensaje: 'Operación correcta',
            icono: Icons.check_circle,
            color: Colors.green,
          ),
        ],
      ),
    );
  }
}

La tarjeta no sabe de dónde vienen el mensaje, el icono o el color: solo los recibe y los muestra. Los datos viajan siempre de arriba hacia abajo en el árbol de widgets, a través de las propiedades.

Como las propiedades son final, el hijo no puede modificarlas. Si un dato tiene que cambiar, es el padre quien vuelve a construir el hijo con un valor distinto.

Propiedades de tipo Widget

Una propiedad también puede ser otro widget. Así el padre decide no solo los datos, sino también parte del contenido. Muchos widgets de Flutter funcionan así: Padding, Center o Card tienen una propiedad child.

class PanelSeccion extends StatelessWidget {
  final String titulo;
  final Widget child;

  const PanelSeccion({
    super.key,
    required this.titulo,
    required this.child,
  });

  @override
  Widget build(BuildContext context) {
    return Card(
      child: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text(titulo, style: const TextStyle(fontSize: 18, fontWeight: FontWeight.bold)),
            const Divider(),
            child,
          ],
        ),
      ),
    );
  }
}

Por convención, cuando un componente recibe un único widget hijo, la propiedad se llama child, y cuando recibe varios, children.

1.5 Eventos y callbacks: comunicación hijo → padre

Ya sabemos enviar datos del padre al hijo. Pero ¿qué ocurre cuando el usuario pulsa un botón que está dentro del componente?

Imagina que queremos añadir a TarjetaAviso un botón para cerrar el aviso. La tarjeta no puede borrarse a sí misma: la lista de avisos pertenece al padre. Lo que sí puede hacer es avisar al padre de que el usuario ha pulsado el botón, y que el padre decida qué hacer.

Para eso usamos un callback: una función que el padre entrega al hijo como propiedad y que el hijo ejecuta cuando ocurre el evento.

Las funciones también son valores

En Dart una función se puede guardar en una variable o pasar como parámetro, igual que un número o un texto. Ya lo has hecho muchas veces:

ElevatedButton(
  onPressed: () {
    print('Pulsado');
  },
  child: const Text('Aceptar'),
)

onPressed es una propiedad que recibe una función. El botón no sabe qué tiene que hacer: solo sabe que, cuando lo pulsen, debe ejecutar la función que le hayan pasado. Nuestros componentes van a funcionar igual.

VoidCallback: un evento sin datos

Flutter define el tipo VoidCallback para las funciones que no reciben nada y no devuelven nada. Equivale a void Function().

class TarjetaAviso extends StatelessWidget {
  final String mensaje;
  final IconData icono;
  final Color color;
  final VoidCallback? alCerrar;

  const TarjetaAviso({
    super.key,
    required this.mensaje,
    this.icono = Icons.info,
    this.color = Colors.blue,
    this.alCerrar,
  });

  @override
  Widget build(BuildContext context) {
    return Card(
      child: Padding(
        padding: const EdgeInsets.all(16),
        child: Row(
          children: [
            Icon(icono, color: color),
            const SizedBox(width: 12),
            Expanded(child: Text(mensaje)),
            if (alCerrar != null)
              IconButton(
                icon: const Icon(Icons.close),
                onPressed: alCerrar,
              ),
          ],
        ),
      ),
    );
  }
}
  • VoidCallback?: el signo ? indica que la propiedad puede ser null. Así el callback es opcional: si el padre no lo pasa, la tarjeta funciona como antes.
  • if (alCerrar != null): dentro de una lista de widgets podemos usar if para añadir un elemento solo cuando se cumple una condición. Si no hay callback, no se dibuja el botón.
  • onPressed: alCerrar: el botón ejecutará directamente la función que ha recibido la tarjeta.

El padre decide qué ocurre

Ahora el padre necesita guardar la lista de avisos y poder modificarla, así que pasa a ser un StatefulWidget:

class _PantallaAvisosState extends State<PantallaAvisos> {
  final List<String> _avisos = [
    'Recuerda guardar los cambios',
    'Hay una actualización disponible',
    'Entrega la práctica el viernes',
  ];

  void _cerrarAviso(int indice) {
    setState(() {
      _avisos.removeAt(indice);
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Mis avisos')),
      body: ListView.builder(
        itemCount: _avisos.length,
        itemBuilder: (context, indice) {
          return TarjetaAviso(
            mensaje: _avisos[indice],
            alCerrar: () => _cerrarAviso(indice),
          );
        },
      ),
    );
  }
}

El recorrido completo es:

  1. El padre crea cada tarjeta y le pasa el mensaje (padre → hijo) y una función alCerrar.
  2. El usuario pulsa la X de una tarjeta.
  3. La tarjeta ejecuta alCerrar, es decir, avisa al padre (hijo → padre).
  4. El padre borra el aviso de su lista dentro de setState().
  5. Flutter vuelve a construir la pantalla, ahora con una tarjeta menos.
⚠️ Error frecuente 
alCerrar: () => _cerrarAviso(indice),   // ✔ pasa una función
alCerrar: _cerrarAviso(indice),         // ✘ la ejecuta ya

En la segunda línea, _cerrarAviso se ejecuta al construir la tarjeta (y Dart da un error, porque no devuelve ninguna función). Con () => creamos una función nueva que llamará a _cerrarAviso solo cuando se pulse el botón. Si la función no tiene parámetros, se pasa por su nombre, sin paréntesis: alPulsar: _reiniciar.

ValueChanged: un evento que envía un dato al padre

A veces el hijo, además de avisar, tiene que enviar un dato. Para eso Flutter define ValueChanged<T>, que equivale a void Function(T valor).

class SelectorCantidad extends StatelessWidget {
  final int cantidad;
  final ValueChanged<int> alCambiar;
  final int minimo;
  final int maximo;

  const SelectorCantidad({
    super.key,
    required this.cantidad,
    required this.alCambiar,
    this.minimo = 0,
    this.maximo = 10,
  });

  @override
  Widget build(BuildContext context) {
    return Row(
      mainAxisSize: MainAxisSize.min,
      children: [
        IconButton(
          icon: const Icon(Icons.remove),
          onPressed: cantidad > minimo ? () => alCambiar(cantidad - 1) : null,
        ),
        Text('$cantidad', style: const TextStyle(fontSize: 22)),
        IconButton(
          icon: const Icon(Icons.add),
          onPressed: cantidad < maximo ? () => alCambiar(cantidad + 1) : null,
        ),
      ],
    );
  }
}

El componente no guarda la cantidad: la recibe del padre y, cuando el usuario pulsa un botón, le envía el nuevo valor con alCambiar(cantidad + 1). Es el padre quien la guarda:

int _personas = 2;

// dentro del build del padre
SelectorCantidad(
  cantidad: _personas,
  minimo: 1,
  maximo: 8,
  alCambiar: (nuevoValor) {
    setState(() {
      _personas = nuevoValor;
    });
  },
)

Fíjate en onPressed: ... : null. Cuando un botón recibe null en onPressed, Flutter lo dibuja desactivado. Así impedimos bajar del mínimo o pasar del máximo.

¿Por qué el estado está en el padre?

Podríamos haber hecho SelectorCantidad como StatefulWidget y guardar la cantidad dentro. Funcionaría, pero el padre no sabría cuántas personas ha elegido el usuario y no podría usar ese dato.

Por eso es habitual que los componentes reutilizables sean StatelessWidget: reciben los datos por propiedades y comunican los cambios con callbacks. El estado se guarda en el widget que lo necesita. A esta técnica se la llama subir el estado (lifting state up).

Cuando muchas pantallas necesitan el mismo estado, pasarlo de padre a hijo y de hijo a padre se vuelve incómodo. Esa es la limitación de setState() que resolveremos más adelante con Provider.

Resumen

Dirección Cómo se hace Ejemplo
Padre → hijo Propiedades del constructor TarjetaAviso(mensaje: 'Hola')
Hijo → padre, sin datos VoidCallback alCerrar: () => _cerrarAviso(i)
Hijo → padre, con un dato ValueChanged<T> alCambiar: (valor) { ... }
Hijo → padre, con varios datos Un tipo de función propio final void Function(String nombre, int edad) alGuardar;
Sobre los nombres: los widgets de Flutter llaman a sus callbacks onAlgo (onPressed, onChanged, onTap). En nuestros componentes usamos nombres en español con el mismo patrón: alCerrar, alCambiar, alPulsar. Lo importante es que el nombre indique cuándo se ejecuta la función.
